# AGENTS.md

## Lessons

- Python Playwright is not installed on this machine, so `from playwright.sync_api import ...` fails. Check for it before you plan a screenshot step.
- The heavy-gate PreToolUse hook blocked an inline `python3 -c "import playwright"` check, but heredoc Python (`python3 -I - <<EOF`) ran fine. For anything that might launch a browser, write it to a file and run it through `~/.claude/bin/heavy-gate`.
- ELI5 diagrams: if two figures show the same example, they must use the same attention percentages. Draw share bars as a fraction of 100%, not scaled to the largest value.
- ELI5 copy in Chinese: when you introduce a technical term (e.g. 序列转换), put the English original in parentheses right after it, e.g. “序列转换”（sequence transduction）. For an abbreviation, spell out the full English name too, e.g. RNN（Recurrent Neural Network，循环神经网络）.
- ELI5 timelines: name every node at the same level (all specific systems like Seq2Seq / GNMT, or all model families like RNN / LSTM). Mixing a family name with a specific system once made it look as if LSTM came before RNN, when LSTM is a 1997 improved RNN.
- ELI5 "why the old way fails" sections: a one-line summary was judged too vague. Give each flaw its own heading and figure, and spell out the mechanism (e.g. h₃ must wait for h₂), an analogy, and a concrete example sentence.
- ELI5 wording: an abstract metaphor ("RNN 是零件，Seq2Seq 是组装方式") was judged harder to follow than precise terms. Prefer short formal definitions (架构 architecture vs 网络 network), and keep metaphors only when they are concrete.
- ELI5: never name a mechanism in passing (e.g. "注意力是 RNN 的外挂"). If you mention it, explain what problem it solves, how it works step by step, why it can be bolted on, and what it still leaves unsolved.
- ELI5 speed claims: always say which phase. Transformer is parallel in training (the answer is known, so teacher forcing + mask can run every position at once), but it still generates one word at a time at inference, like RNN. Never write a bare "不排队 / 1 步".
- ELI5 paper explainers: state the paper's core question and how it answers it, not just its mechanisms. For this paper that is the RNN / RNN+attention / CNN / attention comparison (training parallelism and path length, i.e. Table 1). Anything compared, such as CNN, must also be explained.
- ELI5 page structure: the page was judged tedious and jumpy. Keep one causal storyline (task → old method → its flaws → each patch, with what it fixed and what it left → the paper's question → its answer → results), number the section kickers, and add a one-line roadmap. Introduce every term before first use (GRU once appeared in a figure with no intro), make each point once (the title's meaning, "training still queues"), keep one figure per idea, and keep captions to what the figure does not already show.
- ELI5 long-range dependencies: explain both directions of path length. Forward, information fades; backward, which matters more, the gradient is multiplied by a factor at every step (0.9¹⁰ ≈ 0.35, 0.9⁵⁰ ≈ 0.005), i.e. vanishing / exploding gradients. A one-line mention of 梯度 was not enough.
- ELI5 formulas: explain every symbol and step that is not obvious (e.g. the √d_k in scaled dot-product attention), with a concrete numeric example (scores 24/16/8/0 with no scaling, ÷8 and ÷64) rather than only showing the formula.
- ELI5 multi-head attention: show why one head is not enough (one softmax sums to 100% and blends everything into one vector), how heads differ (each has its own learned Q/K/V projection), and the numbers (512 = 8 heads × 64, which is where d_k = 64 comes from; concat then W_O; cost about the same as one full head). When a later figure shows different percentages for the same example, say why.
- ELI5 two versions: the page comes in two separate HTML files linked by a toggle bar at the top. `index.html` is the deep version (深入版), built with `python3 gen.py index.html tpl.html`. `simple.html` is the 9db8ecf snapshot (简易版), built with `python3 gen_simple.py simple.html tpl_simple.html`. The user chose two files over one page with a JS toggle. Keep the simple version as it was: apply new lessons only to the deep version unless asked. For example, the user chose to leave the simple footer's bare "不排队" as is.
- Git commits: a PreToolUse hook blocks commit messages with a co-author trailer, and it scans the whole Bash command. Commit without the trailer, in a command of its own.
- ELI5 third page: `read-write-pick.html` (读 · 写 · 选, a cheat sheet of the whole encoder → decoder → output flow) is hand-written, with no generator; edit it directly. When you change the toggle bar, update all three: `tpl.html`, `tpl_simple.html` and `read-write-pick.html`. It uses the same palette, fonts and card/section styles as `tpl.html` (`--panel`, `--accent`, `--body`, ...). Its phase colors are aliases: 读 `--read` = `--h2` blue, 写 `--write` = `--h3` green, 选 `--pick` = `--accent`. When the other pages' style changes, copy the change here; the user asked for the three pages to look alike. On screens 520px wide or less the bar hides the `<small>` subtitles so three buttons fit on a phone.
- ELI5 layers vs heads: readers mixed up 多头 (heads side by side in one layer, all reading the same input) and 多层 (layers stacked, each reading the one below). The deep version explains both in 6 ④, with the FFN: attention only takes weighted averages of V, and the FFN builds new features from them. Use the 小狗/它/累 example so the percentages match the multi-head section.
- ELI5 page shell: all three pages must start with the same skeleton (`<!doctype html>`, charset, viewport, `<style>body{margin:0}...</style>`), as `read-write-pick.html` does. `tpl.html` / `tpl_simple.html` once lacked it, so opened locally they ran in quirks mode with the default 8px body margin. That pushed the toggle bar 8px down and in, and switching to the third page looked like the bar had changed height. The generators copy the template verbatim, so the skeleton lives in the templates. To compare pages, measure `.ver` with `getBoundingClientRect()` (node + playwright-core from a sibling repo, run through heavy-gate) rather than comparing CSS.
- Screenshots: `ai-eli5`'s playwright-core wants a headless-shell build that isn't installed (1248), so `chromium.launch()` fails. Pass `executablePath: '/root/.cache/ms-playwright/chromium_headless_shell-1243/chrome-headless-shell-linux64/chrome-headless-shell'`.
- ELI5 section 8 (后来) must keep the causal bridge: parallel training → models can scale, plus label-free next-word / fill-in-the-blank data, then GPT = decoder only and BERT = encoder only. A bare timeline was judged abrupt after the detailed sections. "大号模型" in section 7 means Transformer-big; don't call it "大模型", which reads as LLM.
- ELI5 browser titles: all three pages and both templates use `<title>注意力就是全部</title>` so switching versions does not change the browser tab title. Keep the page headings and switcher labels distinct.
